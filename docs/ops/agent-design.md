# 섬업 에이전트 설계안

기준: "직무별 분업 금지, 생성 에이전트 1개 + 단위별 전담 에이전트". 가정: 운영자는 1명, 작업 단위는 '줄기' 7개, 결과물은 사이트 화면과 본부의 할 일 목록.

## 1. 한 줄 요약
섬업 사이트의 7개 줄기를 줄기마다 하나씩 붙은 전담 에이전트가 살피고, 데이터는 공공 API로 자동으로 채우며, 사람은 승인만 한다.

## 2. 작업 단위 정의
- 단위: **줄기** (거래·창업정보·인사이트·해커톤·소통·제주살이·협업)
- 단위마다 따로 갖는 것: 자기 데이터 파일, 자기 규칙, 자기 기억(지운 제안·배운 것), 자기 길잡이 파일(`docs/brain/<줄기>.md`)
- 모두가 공유하는 기본 틀: 사실은 출처가 있어야 한다, 숫자는 코드가 읽는다, 글·코드는 사람 승인 없이 바꾸지 않는다, 결정은 `PROJECT.md`에 기록

## 3. 생성 에이전트
- 언제: 새 줄기가 생길 때만. 본부(`/hq.html`)의 "＋ 줄기" 버튼
- 받는 정보: 줄기 이름, 목표 한 줄, 보는 숫자, 데이터 파일(있으면)
- 만들어 내는 것: 기본 틀(`TEMPLATE`)이 붙은 전담 에이전트와 빈 기억. 그 줄기만의 숫자 읽기 규칙과 길잡이 파일은 다음 코드 작업 때 더한다. 기존 에이전트는 건드리지 않는다

## 4. 전담 에이전트 (줄기 하나 기준)
- 맡는 일: 자기 데이터 읽기(`sense`) → 할 일 제안(`propose`) → 회의록에 한 줄 보고. 한 에이전트가 이 순서로 끝까지 한다
- 기억: 운영자가 지운 제안은 다시 내지 않는다(`memory.dismissed`). 끝낸 일도 다시 내지 않는다
- 도구: 자기 줄기의 JSON 파일, 자기 피드(공공 API)
- 하지 않는 것: 다른 줄기 데이터 읽기, 다른 에이전트 호출, 글·코드 수정

## 5. 흐름
- 새 줄기: 운영자 → "＋ 줄기" → 전담 에이전트 생성
- 평소: 하루 1번 예약 실행(또는 "지금 회의") → 줄기별 전담 에이전트가 각자 제안 → 본부에 '제안'으로 쌓임 → 운영자가 진행·완료·삭제
- 코드 작업: 운영자가 Claude Code에 줄기 하나의 일을 맡김 → 그 줄기 길잡이 파일만 읽고 작업 → 운영자 확인

## 6. 사람 확인 지점
- 제안을 '진행'으로 바꾸는 것: 운영자, 본부 화면에서
- 사실 정보 게시(지원사업·인사이트·생활정보): 운영자, 관리자 화면에서
- 코드 변경 반영(커밋·배포): 운영자

## 7. 설계 점검표
- 작업 하나에 부르는 에이전트가 하나뿐인가? **예** (줄기의 전담 에이전트)
- 직무 이름으로 나뉜 에이전트가 없는가? **예** (줄기로만 나눔)
- 전담 에이전트끼리 서로 부르거나 데이터를 공유하지 않는가? **예**
- 단위를 늘릴 때 생성만 하면 되고 기존 것은 그대로인가? **예**

## 8. 처음엔 빼도 되는 것 (붙일 순서대로)
1. 코드까지 자동으로 고치는 예약 작업
2. 줄기별 주간 요약을 스레드 글 초안으로 만들기
3. 로그인 기반 추천(도배 방지)
4. 네이버 지도로 교체, 주소→좌표 변환

## 9. 토큰을 아끼는 규칙
- 데이터 수집·숫자 계산·제안은 전부 코드. AI 토큰 0
- 회의록 AI는 숫자가 바뀌었을 때만, 하루 1번, 25초 안에 답이 없으면 건너뜀
- 사용자용 AI(글쓰기·버리는 법)는 버튼을 눌렀을 때만. 자주 묻는 것은 기본 지식표가 먼저 답함
- Claude Code 작업은 길잡이 파일 하나만 읽고 시작, 반복 절차는 스킬로
- 공공 API 응답은 파일에 저장해 두고 주기(6~24시간)마다만 다시 받음
